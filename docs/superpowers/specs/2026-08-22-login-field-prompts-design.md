# `/newapi-login` 字段提示设计

## 背景

当前网站地址和账号输入使用统一标题 `New API 登录`，字段含义仅放在 placeholder 中。用户开始输入后 placeholder 消失，因此无法确认当前正在填写网站地址还是账号。密码使用自定义掩码输入，已有持久的 `密码:` 标签，但三步的视觉表达不一致。

## 目标

- 用户在输入过程中始终能看到当前字段。
- 明确显示登录流程进度。
- 密码继续以掩码显示，不回显明文。
- 不改变取消、校验、网络登录、配置保存或生命周期行为。

## 交互设计

登录流程保持三步顺序，并使用持续可见的标题：

1. `New API 登录（1/3）：网站地址`
2. `New API 登录（2/3）：账号`
3. `New API 登录（3/3）：密码`

网站地址输入的 placeholder 只承担辅助说明：未配置时显示 URL 示例，已有配置时提示留空沿用当前地址。账号输入不依赖 placeholder 表达字段含义。密码自定义控件显示第三步标题，并继续将每个输入字符渲染为 `*`。

## 实现边界

- 将三步标题定义为集中常量，避免文案散落和步骤编号不一致。
- 网站地址与账号继续使用 `ctx.ui.input()`。
- 密码继续使用 `ctx.ui.custom()` 和现有 `Input` 组件。
- 不引入单页表单、额外依赖或凭据预填。
- 不在日志、通知、测试输出或错误消息中包含密码。

## 错误与取消

- Escape 或输入 API 返回 `undefined` 时，仍按现有逻辑取消登录。
- 网站地址为空且没有当前配置时，继续显示现有警告。
- 空账号和空密码继续中止登录，不改变现有语义。
- URL 校验、登录失败、保存失败以及旧账户恢复逻辑保持不变。

## 验证标准

- 源码中三步标题集中且顺序为 1/3、2/3、3/3。
- 网站地址和账号输入使用各自的持久标题。
- 密码输入使用第三步标题并只渲染掩码。
- 现有测试全部通过。
- `npm run check` 通过。
- npm/Pi Package 可在隔离环境正常加载。
